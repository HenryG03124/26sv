# 2026-09-23 转向修正幅度与短暂丢线处理

针对 2026-09-22 录屏中弯道修正偏弱、短暂丢线后方向归零的问题，修改 `steering.py`。输入接口和 `K_steering = 3` 保持兼容，现有主循环直接使用新控制器。

## 参考与适用范围

查阅了 GitHub 上 PythonRobotics 的以下实现：

- [Pure pursuit](https://github.com/AtsushiSakai/PythonRobotics/blob/master/PathTracking/pure_pursuit/pure_pursuit.py)：速度相关的预瞄距离，以及独立的最大转角限制。
- [Stanley](https://github.com/AtsushiSakai/PythonRobotics/blob/master/PathTracking/stanley_control/stanley_control.py)：航向误差和横向误差分别参与控制，速度调节横向误差项。

本项目的输入是 640 像素宽图像中的中心线，没有图像到地面的标定。这里只参考预瞄、误差修正、输出约束分开处理的思路，保留现有图像空间预瞄结构；没有复制上述控制器源码，也没有将像素代入其米制车辆模型。

## 最终行为

- 小于等于 4px 的滤波目标偏差保留原来的偏差增益；4～24px 平滑增加修正力度；达到 24px 时使用增强增益。2px 死区保持不变。
- 大偏差比例项系数从 `0.45 / (1 + (speed / 60)^2)` 改为 `0.65 / hypot(1, speed / 60)`。这里只列出 `K_steering = 3` 的情况。
- 变化率项保留原来的速度衰减、滤波和上限，不跟随比例项一起增强。
- 转向目标上限从 `0.18 / (1 + (speed / 55)^2)` 改为 `0.18 / hypot(1, speed / 70)`。全局上限仍为 0.18，增加转向和回正的速率分别仍为每秒 0.25、0.5。目标上限变化后，已发送的输出仍按速率约束过渡。
- 丢线时保持最近输出，保持时间从最近一次有效路径计时，取 0.18 秒与按当前速度行驶 3 米所需时间中的较小值。连续丢线不会刷新期限，也不会继续增加转向；过期后按时间回正。3 米是保持期限的计算预算，实际控制更新存在采样和执行延迟。
- 突然跳变的中心线需要持续约 0.12 秒、处于同一个偏差范围内才接受。孤立跳变不会替换已接受的路径参考，也不会产生微分尖峰；确认后的新路径仍经过输出速率限制。
- 启动时没有有效路径、控制增益无效、时钟断续等情况不沿用旧保持状态。非有限车速按缺失遥测处理。
- `steering_debug` 新增实际输出、未限幅目标、饱和、速率受限、增强比例、保持期限和路径重新确认等诊断信息。丢线分支也记录状态和路径年龄。
